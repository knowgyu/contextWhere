# v0.5.0 — audited local backup and restore

## 요약

0.5.0은 contextWhere를 다른 디렉터리나 장비에서 재현할 수 있도록 `work_wiki/`와 `.contextwhere/`를 하나의 manifest 포함 zip으로 묶고, 빈 target에만 복원하는 백업/복원 기반을 추가한다.

## 변경 사항

- `contextwhere backup create --output <zip> --json` 추가.
- `contextwhere backup restore <zip> <target_root> --json` 추가.
- Backup manifest `contextwhere-backup-manifest.json` 추가.
- Archive member를 `work_wiki/`와 `.contextwhere/` 아래로 제한하고 `.contextwhere/backups/`는 제외해 recursive backup bloat를 막는다.
- Restore는 non-empty target root를 거부한다.
- Backup/restore roundtrip, overwrite refusal, recursive backup exclusion, path traversal rejection 테스트 추가.

## 안전 경계

- Provider 원본 저장소나 임의 로컬 경로는 백업하지 않는다.
- Archive member path traversal과 지원되지 않는 top-level member를 거부한다.
- 기존 root 위로 덮어쓰지 않는다.
- 백업은 local zip 파일 생성만 수행하며 network upload는 하지 않는다.

## 검증

- `python -m compileall -q src tests`
- `pytest -q` → 39 passed
- `npx --yes pyright src tests` → 0 errors, 0 warnings
- `contextwhere backup create/restore` temp-root smoke → restored root에서 query 성공
- `contextwhere lint --json` → ok true

## 남은 리스크

- 대용량 운영 백업과 장기 보관 정책은 별도 운영 정책으로 보강해야 한다.
- Backup format migration/version negotiation은 후속 0.5.x에서 다룬다.
- Windows path edge case는 추가 실사용 검증이 필요하다.
