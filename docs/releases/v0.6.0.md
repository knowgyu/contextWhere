# v0.6.0 — operational status command

## 요약

0.6.0은 설치·운영·백업 이후 현재 root가 배포 가능한 상태인지 빠르게 확인할 수 있도록 `contextwhere status --json` read-only 점검 명령을 추가한다.

## 변경 사항

- `contextwhere status --json` 추가.
- Version, root paths, DB/wiki 존재 여부, evidence/ingest/entity/relationship/recall counts를 보고한다.
- Latest ingest, backup count, lint error/warning count를 보고한다.
- Missing root에서도 state를 생성하지 않고 structured `ok:false`를 반환한다.
- `contextwhere verify --json` smoke에 status step 추가.

## 안전 경계

- Status는 read-only이며 DB, wiki, `.contextwhere` 디렉터리를 생성하지 않는다.
- Exit code 0은 DB와 wiki가 존재하고 lint error가 없을 때만 반환한다.
- 전체 lint issue는 최대 10개만 출력해 agent/CI 로그를 과도하게 키우지 않는다.

## 검증

- `python -m compileall -q src tests`
- `pytest -q` → 41 passed
- `npx --yes pyright src tests` → 0 errors, 0 warnings
- `contextwhere verify --json` → ok true, includes `status`
- `contextwhere status --json` temp-root smoke → counts/latest ingest/backup count 확인

## 남은 리스크

- Provider compatibility matrix와 migration 상태 점검은 후속 0.6.x에서 확장해야 한다.
- Status 출력 포맷은 1.0 이전까지 backward-compatible 필드 정책을 문서화해야 한다.
